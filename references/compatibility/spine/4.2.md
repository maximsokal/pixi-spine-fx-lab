# Spine Runtime 4.2 — opt-in export/runtime adapter specification

**Status:** pinned project baseline with PixiJS 8.22.0. This file provides instructions/risks, **not** working support in v0.1.0.

## Compatibility / supported pair selection
Official `@esotericsoftware/spine-pixi-v8` **4.2.120** (PixiJS 8.22.0) is current tested baseline; official `@esotericsoftware/spine-pixi-v7` 4.2.x is an alternate *unverified* PixiJS 7 profile.

**Export rule:** the original Spine Editor that produced the .json/.skel file must be 4.2.x; a mismatched runtime major.minor must be rejected before display or baking. Export patches may differ within the same 4.2 family.

## How to connect (future approved editor adaptation)
1. Read `../contract.md`, `../qa-matrix.md`, the chosen `../pixi/<version>.md` and `../legacy-policy.md` if using a community/historic version. Do not load all versions by default.
2. Inspect the user's *actual* Spine export version and original editor source, plus JSON/SKEL/atlas pages. Reject mismatched target runtime; where a different editor version is needed, explicitly re-export from original `.spine`, not string-edit JSON headers.
3. Create an isolated generated-editor working directory. Keep original vendor pins, Doctor head sample, baseline HTML, and `SKILL.md` unchanged. Resolve exact patches + peer support first.
4. Dependencies: Baseline: `npm install --save-exact pixi.js@8.22.0 @esotericsoftware/spine-pixi-v8@4.2.120` for a standalone developer example; the offline editor already vendors these exact versions. For v7 profile: replace with `pixi.js@<EXACT_V7> @esotericsoftware/spine-pixi-v7@<EXACT_4_2_PATCH>` after checking real package availability. **Replace all placeholders with published exact patches; placeholders must not be executed literally.**
5. Asset loading and Spine object creation: Official runtime registers Pixi Assets skeleton/atlas loader extensions; load matching `.json` or `.skel` and `.atlas` plus every image page. 4.2 uses `Spine.from({ skeleton:'skeletonAlias', atlas:'atlasAlias', autoUpdate:false })` after Assets registration. Current editor constructs from `skeletonData` manually; retain/audit this existing advanced path rather than replacing it automatically.
6. Map `Spine.state`, `Spine.skeleton`, animation update/manual ticking, skin selection, bounds, attachment geometry/clipping, mesh, alpha/atlas PMA, and destruction to the selected API. DO NOT run both legacy and official loaders in one Pixi instance.
7. Preserve the same effect implementation for live/bake/dev ZIP and 60-FPS deterministic timeline; create runtime-matched local sample and both JSON/SKEL fixtures, validate renderer compatibility and alpha, and update developer package dependencies only in an approved adapted editor.
8. Run the compatibility matrix VC-01..VC-16 and report PASS/FAIL/NOT RUN, package hash, actual renderer, source commit and specific omissions before declaring support.

## Version-specific behavior and feature differences
Real baseline includes meshes, clipping, multipage atlases, skins, animations and sequence attachments; test actual Physics Constraints where present. The built-in Doctor head JSON reports 4.2.43 and includes a two-page atlas. Do not infer 4.3 data support.

### What changes versus shipped Spine 4.2 baseline
This is the *identity* profile: no version switch or vendor change. Switching PixiJS 8.22 to PixiJS 7 requires GL-only rewrite; switching to Spine 4.3 requires re-export and new constructor/cache audits. PMA PNG bug #1/#2 is a known independent quality requirement.

## Test fixtures & negative coverage
Built-in Doctor head 4.2 sample (JSON, two atlas pages, sequences) plus authentic 4.2 SKEL + weighted mesh/clipping, Physics (if supported), and negative 4.1 and 4.3 data.

## Hard constraints
- One runtime major.minor parser per profile; no guaranteed cross-version decoding. Additional Spine versions and multiple simultaneous runtimes are separate research/design.
- Only exact version-matched atlas/data without a user-confirmed re-export is accepted.
- The editor's alpha/texture handling, geometry sampling and filters require backend-specific tests; a visible skeleton alone is not proof.
- No runtime or vendor files are copied/updated by this document.
- Do not call `SKILL.md` a full catalog. Future approved routing loads only this file plus selected Pixi module.

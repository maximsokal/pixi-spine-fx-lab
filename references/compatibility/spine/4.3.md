# Spine Runtime 4.3 — opt-in export/runtime adapter specification

**Status:** maintained official packages exist; adapter NOT implemented in this project. This file provides instructions/risks, **not** working support in v0.1.0.

## Compatibility / supported pair selection
Official `@esotericsoftware/spine-pixi-v8` 4.3.x with PixiJS 8 (supported family) or `@esotericsoftware/spine-pixi-v7` 4.3.x with PixiJS 7 (supported family). Exact patches and tested Pixi peer ranges must be pinned and validated.

**Export rule:** the original Spine Editor that produced the .json/.skel file must be 4.3.x; a mismatched runtime major.minor must be rejected before display or baking. Export patches may differ within the same 4.3 family.

## How to connect (future approved editor adaptation)
1. Read `../contract.md`, `../qa-matrix.md`, the chosen `../pixi/<version>.md` and `../legacy-policy.md` if using a community/historic version. Do not load all versions by default.
2. Inspect the user's *actual* Spine export version and original editor source, plus JSON/SKEL/atlas pages. Reject mismatched target runtime; where a different editor version is needed, explicitly re-export from original `.spine`, not string-edit JSON headers.
3. Create an isolated generated-editor working directory. Keep original vendor pins, Doctor head sample, baseline HTML, and `SKILL.md` unchanged. Resolve exact patches + peer support first.
4. Dependencies: For Pixi 8 `npm install --save-exact pixi.js@<VERIFIED_8_PATCH> @esotericsoftware/spine-pixi-v8@<EXACT_4_3_PATCH>`; for Pixi 7 choose `pixi.js@<VERIFIED_7_PATCH> @esotericsoftware/spine-pixi-v7@<EXACT_4_3_PATCH>`. This is a future isolated profile, not automatic baseline replacement. **Replace all placeholders with published exact patches; placeholders must not be executed literally.**
5. Asset loading and Spine object creation: Load Spine **4.3.x** exports and full matching atlas. Official docs specify 4.3+ constructor `new Spine({skeleton:'alias',atlas:'alias',autoUpdate:false})` and `Spine.createOptions({...})`; `Spine.from` is deprecated in 4.3 and scheduled for removal in 4.4. The baseline manual `new Spine({skeletonData})` path must be re-audited for this API and caching behavior.
6. Map `Spine.state`, `Spine.skeleton`, animation update/manual ticking, skin selection, bounds, attachment geometry/clipping, mesh, alpha/atlas PMA, and destruction to the selected API. DO NOT run both legacy and official loaders in one Pixi instance.
7. Preserve the same effect implementation for live/bake/dev ZIP and 60-FPS deterministic timeline; create runtime-matched local sample and both JSON/SKEL fixtures, validate renderer compatibility and alpha, and update developer package dependencies only in an approved adapted editor.
8. Run the compatibility matrix VC-01..VC-16 and report PASS/FAIL/NOT RUN, package hash, actual renderer, source commit and specific omissions before declaring support.

## Version-specific behavior and feature differences
Use 4.3 export fixtures with active advanced features and verify all required behaviors (including physics, clipping, deform and sequences as applicable). Since version metadata and data layout change, **do not read 4.2 exports with a 4.3 parser** or merely change header strings. Re-export from `.spine` using Spine Editor 4.3.x.

### What changes versus shipped Spine 4.2 baseline
New constructor/asset option flow, potentially different cache lifecycle; official docs discuss `unloadFromCache()` before destruction of shared cached SkeletonData. New 4.3 exports/runtime features need independent visual/perf verification. Pixi 8 WebGPU still requires WGSL; Pixi 7 remains WebGL only.

## Test fixtures & negative coverage
Original authored `.spine` re-exported by 4.3 to matching JSON and SKEL, multipage atlas, advanced representative rigs, animations, load-unload cache lifecycle, negative 4.2 fixture.

## Hard constraints
- One runtime major.minor parser per profile; no guaranteed cross-version decoding. Additional Spine versions and multiple simultaneous runtimes are separate research/design.
- Only exact version-matched atlas/data without a user-confirmed re-export is accepted.
- The editor's alpha/texture handling, geometry sampling and filters require backend-specific tests; a visible skeleton alone is not proof.
- No runtime or vendor files are copied/updated by this document.
- Do not call `SKILL.md` a full catalog. Future approved routing loads only this file plus selected Pixi module.

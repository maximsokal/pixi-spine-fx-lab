# Spine Runtime 4.1 — opt-in export/runtime adapter specification

**Status:** legacy community or deprecated official adapter proposal. This file provides instructions/risks, **not** working support in v0.1.0.

## Compatibility / supported pair selection
`pixi-spine` v3.x (Pixi 5/6) or v4.x (Pixi 7), OR historic EsotericSoftware `spine-pixi` for Pixi 7 (deprecated; official docs recommend maintained `spine-pixi-v7` for supported newer releases). **Not supported by official 4.2/4.3 v8 packages.**

**Export rule:** the original Spine Editor that produced the .json/.skel file must be 4.1.x; a mismatched runtime major.minor must be rejected before display or baking. Export patches may differ within the same 4.1 family.

## How to connect (future approved editor adaptation)
1. Read `../contract.md`, `../qa-matrix.md`, the chosen `../pixi/<version>.md` and `../legacy-policy.md` if using a community/historic version. Do not load all versions by default.
2. Inspect the user's *actual* Spine export version and original editor source, plus JSON/SKEL/atlas pages. Reject mismatched target runtime; where a different editor version is needed, explicitly re-export from original `.spine`, not string-edit JSON headers.
3. Create an isolated generated-editor working directory. Keep original vendor pins, Doctor head sample, baseline HTML, and `SKILL.md` unchanged. Resolve exact patches + peer support first.
4. Dependencies: Choose ONE historical runtime integration after reading license and actual package availability: community `pixi-spine` with exact patch or archived `spine-pixi` 4.1 if verifiably available for Pixi 7. Do not assume `@esotericsoftware/spine-pixi-v7@4.1` is a valid published tag. **Replace all placeholders with published exact patches; placeholders must not be executed literally.**
5. Asset loading and Spine object creation: For community mode, verify `pixi-spine` loader registration and `new Spine(resource.spineData)`; for official historic `spine-pixi`, inspect its actual exported API on its 4.1 tag before specifying constructor. Do not mix both loaders in one Pixi instance.
6. Map `Spine.state`, `Spine.skeleton`, animation update/manual ticking, skin selection, bounds, attachment geometry/clipping, mesh, alpha/atlas PMA, and destruction to the selected API. DO NOT run both legacy and official loaders in one Pixi instance.
7. Preserve the same effect implementation for live/bake/dev ZIP and 60-FPS deterministic timeline; create runtime-matched local sample and both JSON/SKEL fixtures, validate renderer compatibility and alpha, and update developer package dependencies only in an approved adapted editor.
8. Run the compatibility matrix VC-01..VC-16 and report PASS/FAIL/NOT RUN, package hash, actual renderer, source commit and specific omissions before declaring support.

## Version-specific behavior and feature differences
4.1 assets need 4.1 parser, 4.1-specific constraint/mesh/clipping API; modern 4.2 physics constraints/sequence behavior cannot be assumed. Re-export 4.1 `.spine` project in 4.2/4.3 only if change of runtime is explicitly requested and validated.

### What changes versus shipped Spine 4.2 baseline
The official maintained packages target newer Spine lines; 4.1 needs archived/community bridge and Pixi 7 or older. Changing Pixi 8 baseline to old bridge is a new separate editor profile, not default fallback.

## Test fixtures & negative coverage
Authentic 4.1 JSON/SKEL + atlas, animation graph, skins/meshes/clipping, wrong-version 4.2 sample and missing-page negatives.

## Hard constraints
- One runtime major.minor parser per profile; no guaranteed cross-version decoding. Additional Spine versions and multiple simultaneous runtimes are separate research/design.
- Only exact version-matched atlas/data without a user-confirmed re-export is accepted.
- The editor's alpha/texture handling, geometry sampling and filters require backend-specific tests; a visible skeleton alone is not proof.
- No runtime or vendor files are copied/updated by this document.
- Do not call `SKILL.md` a full catalog. Future approved routing loads only this file plus selected Pixi module.

# PixiJS 8 — opt-in engine adapter specification

**Status:** baseline for 8.22.0, conditional official support for 4.2/4.3. This is documentation only, not an implemented adapter. **Default remains PixiJS 8.22.0.**

## Which Spine runtimes can attach?
`@esotericsoftware/spine-pixi-v8` with 4.2.x or 4.3.x runtime matching Spine export; official documentation currently lists PixiJS 8 minimum 8.16 (reverify for selected runtime patch)

**Candidate export versions:** Pinned 8.22.0 + official 4.2.120 fully baseline; alternate Pixi 8 patches and Spine 4.3 are NOT automatically certified.

## How to connect this version (future implementation, after review and approval)
1. Detect the user's explicit Pixi target and matching Spine export major.minor. Read `../contract.md`, selected `../spine/<version>.md`, `../qa-matrix.md`, and `../legacy-policy.md` for legacy engines.
2. Create an isolated working copy of the editor. Do NOT overwrite the installed skill, pinned vendor files, `assets/Spine_Burn_Lab.html` or baseline manifest. Verify exact npm patch and peer dependency compatibility first.
3. Install with exact pinned packages: `npm install --save-exact pixi.js@8.22.0 @esotericsoftware/spine-pixi-v8@4.2.120` (baseline ONLY); for alternate exact pinned versions replace both after QA.. **Angle-bracket placeholders are NOT executable commands; replace them with tested published patches.**
4. Initialize the engine using version-specific semantics: `const app = new PIXI.Application(); await app.init({preference:'webgl',backgroundAlpha:0}); document.body.appendChild(app.canvas);`
5. Load a matching-version skeleton and all atlas textures: `Assets.add`/`Assets.load` register skeleton and atlas aliases; official runtime installs loader plugins. 4.2 `Spine.from({skeleton,atlas})`; 4.3 `new Spine({skeleton,atlas})`, `from` deprecated. Current editor manually constructs instances with `skeletonData`, which must be verified on target patch.
6. Adapt FX shaders and uniforms: Use Pixi 8 `Filter({ glProgram: GlProgram.from({vertex,fragment}), gpuProgram: GpuProgram.from({vertex,fragment}), resources: {uniforms: ...} })` contract adapted to exact runtime and shaders; define GLSL for WebGL and WGSL for WebGPU. Do not assume a GLSL-only effect works under WebGPU.
7. Audit texture/render-target and PNG bake path: Pixi 8 TextureSource/ImageSource, explicit alphaMode, render target and WebGPU copy-to-buffer with 256-byte row alignment, BGRA channel handling; WebGL 8.22 extract.canvas PMA bug #1/#2 requires raw-pixel unpremultiply before ImageData.
8. Recreate a version-specific developer integration example and package manifest with honest renderer support; embed all permitted dependencies/assets locally. Run VC-01..VC-16, record actual backend; present results for separate implementation approval.

## Changes relative to PixiJS 8.22.0 baseline
Pixi v8 async initialization; WebGL/WebGPU selectable, Canvas has Spine feature limitations (two-color tint, slot objects, blend modes). Patch upgrades can change internal DefaultBatcher helper used by baseline, requiring explicit revalidation.

## Acceptance / gating
- Build pinned baseline unchanged, then selected exact patch with real WebGL1, WebGL2, WebGPU where available; multi-page 4.2/4.3 skeletal features; PMA straight PNG; filtered layers; fallback, cancel, cleanup and developer ZIP.
- Same user effect implementation must power editor preview, isolated 60 FPS PNG bake and version-pinned developer ZIP; no duplicated misleading effect code.
- Root `SKILL.md` must NOT contain this whole module; add at most a conditional route later after explicit approval.
- Stop if selected Spine package is unverified, the project requires unsupported features or the user requests WebGPU on an unsupported Pixi generation.

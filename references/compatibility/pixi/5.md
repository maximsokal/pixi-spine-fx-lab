# PixiJS 5 — opt-in engine adapter specification

**Status:** legacy, community research only. This is documentation only, not an implemented adapter. **Default remains PixiJS 8.22.0.**

## Which Spine runtimes can attach?
`pixi-spine` v3.x for Spine 3.7 / 3.8 / 4.0 / 4.1, subject to exact bundle/loader verification

**Candidate export versions:** Spine 3.7, 3.8, 4.0, 4.1 through a version-specific community loader (candidate only).

## How to connect this version (future implementation, after review and approval)
1. Detect the user's explicit Pixi target and matching Spine export major.minor. Read `../contract.md`, selected `../spine/<version>.md`, `../qa-matrix.md`, and `../legacy-policy.md` for legacy engines.
2. Create an isolated working copy of the editor. Do NOT overwrite the installed skill, pinned vendor files, `assets/Spine_Burn_Lab.html` or baseline manifest. Verify exact npm patch and peer dependency compatibility first.
3. Install with exact pinned packages: `npm install --save-exact pixi.js@<VERIFIED_5_PATCH> pixi-spine@<VERIFIED_3_PATCH>`. **Angle-bracket placeholders are NOT executable commands; replace them with tested published patches.**
4. Initialize the engine using version-specific semantics: `const app = new PIXI.Application({transparent: true}); document.body.appendChild(app.view);` (verify exact option on selected patch)
5. Load a matching-version skeleton and all atlas textures: Use pinned legacy loader registration and a matching asset parser; documented community path is `import 'pixi-spine'` plus `new Spine(resource.spineData)` after load. Verify `PIXI.Loader` or exact old loader plugin API on pinned package. Do not assume Pixi 7 Assets or Pixi 8 ImageSource.
6. Adapt FX shaders and uniforms: Legacy `new PIXI.Filter(vertexSource, fragmentSource, uniforms)` requires GLSL compatible with its WebGL renderer. Pixi v8 `GlProgram`/WGSL/resources dictionary is not portable.
7. Audit texture/render-target and PNG bake path: Legacy BaseTexture, loader-managed atlas and PMA semantics; map `Texture.from`, texture cache and `RenderTexture` differences from baseline. Verify `extract` plugin or framebuffer readback before PNG encoding.
8. Recreate a version-specific developer integration example and package manifest with honest renderer support; embed all permitted dependencies/assets locally. Run VC-01..VC-16, record actual backend; present results for separate implementation approval.

## Changes relative to PixiJS 8.22.0 baseline
No Pixi 8 async app.init; no WGSL/WebGPU; legacy shader uniforms and renderer initialization; potentially missing tint/mesh/slot support depending community loader. Some 4.1 advanced features require test fixtures, not a claim.

## Acceptance / gating
- Pixi 5 initialisation and WebGL backend proof; community loader for each claimed Spine version; clipping+PMA+weighted mesh; real temporal effect filter; straight-alpha PNG and ZIP. Do not call `app.canvas` as if v8.
- Same user effect implementation must power editor preview, isolated 60 FPS PNG bake and version-pinned developer ZIP; no duplicated misleading effect code.
- Root `SKILL.md` must NOT contain this whole module; add at most a conditional route later after explicit approval.
- Stop if selected Spine package is unverified, the project requires unsupported features or the user requests WebGPU on an unsupported Pixi generation.

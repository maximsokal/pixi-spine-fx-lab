# PixiJS 7 — opt-in engine adapter specification

**Status:** official runtime supported for 4.2/4.3; community research for 3.7–4.1. This is documentation only, not an implemented adapter. **Default remains PixiJS 8.22.0.**

## Which Spine runtimes can attach?
`@esotericsoftware/spine-pixi-v7` for Spine 4.2/4.3 (runtime major.minor must match assets); `pixi-spine` v4.x as a separate community legacy alternative for 3.7–4.1

**Candidate export versions:** Official spine-pixi-v7 requires PixiJS ≥7.2.0 according to Esoteric documentation; PixiJS 7 WebGL only.

## How to connect this version (future implementation, after review and approval)
1. Detect the user's explicit Pixi target and matching Spine export major.minor. Read `../contract.md`, selected `../spine/<version>.md`, `../qa-matrix.md`, and `../legacy-policy.md` for legacy engines.
2. Create an isolated working copy of the editor. Do NOT overwrite the installed skill, pinned vendor files, `assets/Spine_Burn_Lab.html` or baseline manifest. Verify exact npm patch and peer dependency compatibility first.
3. Install with exact pinned packages: `npm install --save-exact pixi.js@<PINNED_7_PATCH> @esotericsoftware/spine-pixi-v7@<MATCHING_4_2_OR_4_3_PATCH>`; select ONE runtime family, do not install community and official loaders by default.. **Angle-bracket placeholders are NOT executable commands; replace them with tested published patches.**
4. Initialize the engine using version-specific semantics: `const app = new PIXI.Application({ backgroundAlpha: 0 }); document.body.appendChild(app.view);` (sync init vs Pixi 8 async)
5. Load a matching-version skeleton and all atlas textures: Official runtime supplies asset extensions. For 4.2 example use `Spine.from({skeleton:'alias',atlas:'alias'})`; for 4.3 use reviewed constructor API. Community path uses separate loader and should not share source code with official API without adapter.
6. Adapt FX shaders and uniforms: Custom `Filter` in v7 uses constructor style `new Filter(vertex, fragment, uniforms)`; port filters and uniform bindings from Pixi 8 `Filter({glProgram, gpuProgram, resources})`. WGSL and WebGPU paths must be disabled.
7. Audit texture/render-target and PNG bake path: Pixi 7 keeps BaseTexture, while Pixi 8 introduces TextureSource. Revisit atlas PMA, meshes, filters and readback API; do not blindly copy v8 extraction.
8. Recreate a version-specific developer integration example and package manifest with honest renderer support; embed all permitted dependencies/assets locally. Run VC-01..VC-16, record actual backend; present results for separate implementation approval.

## Changes relative to PixiJS 8.22.0 baseline
Official v7 provides many Spine features in WebGL but no WebGPU; older Pixi 7 mesh/render/upload behavior needs validation. The 4.3 constructor is a separate Spine major.minor change.

## Acceptance / gating
- True WebGL1/2 when claimed; official vs community selected correctly; 4.2 and 4.3 separate fixtures; WebGPU request rejected rather than silent fallback; PNG and developer ZIP restored.
- Same user effect implementation must power editor preview, isolated 60 FPS PNG bake and version-pinned developer ZIP; no duplicated misleading effect code.
- Root `SKILL.md` must NOT contain this whole module; add at most a conditional route later after explicit approval.
- Stop if selected Spine package is unverified, the project requires unsupported features or the user requests WebGPU on an unsupported Pixi generation.

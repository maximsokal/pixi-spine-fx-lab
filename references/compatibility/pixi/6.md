# PixiJS 6 — opt-in engine adapter specification

**Status:** legacy, community research only. This is documentation only, not an implemented adapter. **Default remains PixiJS 8.22.0.**

## Which Spine runtimes can attach?
`pixi-spine` v3.x for Spine 3.7–4.1, exact patch and loader selected per runtime export

**Candidate export versions:** 3.7/3.8/4.0/4.1 via community pixi-spine v3 candidates (not official pair certification).

## How to connect this version (future implementation, after review and approval)
1. Detect the user's explicit Pixi target and matching Spine export major.minor. Read `../contract.md`, selected `../spine/<version>.md`, `../qa-matrix.md`, and `../legacy-policy.md` for legacy engines.
2. Create an isolated working copy of the editor. Do NOT overwrite the installed skill, pinned vendor files, `assets/Spine_Burn_Lab.html` or baseline manifest. Verify exact npm patch and peer dependency compatibility first.
3. Install with exact pinned packages: `npm install --save-exact pixi.js@<VERIFIED_6_PATCH> pixi-spine@<VERIFIED_3_PATCH>`. **Angle-bracket placeholders are NOT executable commands; replace them with tested published patches.**
4. Initialize the engine using version-specific semantics: `const app = new PIXI.Application({ backgroundAlpha: 0 }); document.body.appendChild(app.view);` (verify exact options for selected patch)
5. Load a matching-version skeleton and all atlas textures: Use community loader extension matching export version; Pixi `Assets` is not bundled in the base v6 package, unlike v7. Verify Loader/Assets integration and multi-page atlases. Do not auto-register every runtime variant.
6. Adapt FX shaders and uniforms: Legacy Pixi Filter constructor and WebGL GLSL path; no WGSL; explicitly port v8 filter `resources`, uniform types and mesh paths to v6 APIs.
7. Audit texture/render-target and PNG bake path: BaseTexture and renderer texture handling differ from Pixi 8 TextureSource; validate atlas PMA, tint and manual low-level readPixels/canvas orientation against exact patch.
8. Recreate a version-specific developer integration example and package manifest with honest renderer support; embed all permitted dependencies/assets locally. Run VC-01..VC-16, record actual backend; present results for separate implementation approval.

## Changes relative to PixiJS 8.22.0 baseline
No WebGPU; different loading and filter systems; particle and geometry extensions differ. Distinct v6 path from v5 should still be separately audited/tested.

## Acceptance / gating
- Pixi 6 actual WebGL version; working loader+Spine matching fixture; tracked memory cleanup; no network; straight-alpha PNG readback oracle; developer integration example and CRC/ZIP.
- Same user effect implementation must power editor preview, isolated 60 FPS PNG bake and version-pinned developer ZIP; no duplicated misleading effect code.
- Root `SKILL.md` must NOT contain this whole module; add at most a conditional route later after explicit approval.
- Stop if selected Spine package is unverified, the project requires unsupported features or the user requests WebGPU on an unsupported Pixi generation.

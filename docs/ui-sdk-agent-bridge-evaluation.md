# FX-AGENT-01 (#68) — UI SDK Agent Bridge evaluation: NO-GO for integration

Reviewed 2026-11-27, repository baseline [13b2ad3](https://github.com/maximsokal/pixi-spine-fx-lab/commit/13b2ad392379180f55494874ea765d59851a9b2d); upstream [655c279](https://github.com/vercel-labs/ui/commit/655c279a07aea370fc2890d3ba564070f204ce4a). This is the completed research deliverable, not a runtime implementation, permission grant, browser compatibility certificate, or approval of a prototype.

## Decision

Retain the specialized native HTML editor and the existing validated FX domain model. Do not install UI SDK or register WebMCP tools in the shipped editor. A future optional agent feature should first implement one narrow, owner-approved domain command boundary, not replace the UI or rely on an accessibility-label-driven executor. Reconsider the SDK as a presentation adapter only if a later measured, version-pinned prototype demonstrates value. Research is complete with a NO-GO recommendation; implementation remains separately gated by #70, #71 and the owner's approval.

### Source-backed evaluation and cost

The upstream source manifests at the reviewed SHA declare **@ui-sdk/core and @ui-sdk/web 0.1.0-beta.18** (Apache-2.0). The web package peers on core (workspace:^ in source); neither declares runtime dependencies beyond that relationship. These are repository manifest versions, not a verified npm installation or lockfile. The /agent entry re-exports core createAgent, agentTools and registerTools. The bridge discovers its registered primitive instances, not arbitrary DOM controls or Pixi objects. The current editor creates ordinary input/select/button nodes, rebuilds selected emitter controls and commits through DOM events. Therefore merely importing /agent cannot make those controls operable. Conversion would require registering/wrapping controls, forwarding typed callbacks, and wiring permission and transactional state. No React dependency is necessary for the web adapter, but the build is an additional ESM bundling/vendoring step; standalone file HTML cannot rely on bare npm imports, CDN, runtime package fetches or lazy external chunks. Vendored production bundle, all reachable chunks, hash, notices, and zero-request checks would be required if adopted. No adoption means zero added SDK bytes/dependencies today.

Upstream gzip budget entries (bytes), NOT locally measured bundle sizes: agent 12086, field 16960, number-input 22499, switch 16169, slider 22370, observe 2786, history 4329. Individual rows include shared core, so adding them does not estimate a combined bundle. The project's actual increment, startup/memory and browser-specific compatibility are unmeasured. A future candidate must measure one combined production entry with only selected components, gzip/raw/inlined HTML sizes and script initialization vs unchanged baseline; no budget or browser support claim until measured. A beta API plus a second state/permission integration is not justified by the current narrow use case.

## Exact mapping to existing code (one optional emitter panel only)

Current sources: assets/template/src/ui.html (FxEmitterUi.mount, cfg.multiEmitters and multiFx.configure), emitter-ui.js (commit, changeEmitter, changeLayer, setFromScene, refresh), emitter-core.js (normalize/serialize/deserialize/sample and stable IDs), emitter-runtime.js (configure, resolved geometry/diagnostics), curve-editor.js, color-ui.js, timeline-core.js. Constraints: references/contracts/parameters.md and product-contract.md; existing scripts/test_emitters.cjs and test_emitter_editor.cjs. No general editor rewrite.

| Task | UI SDK option after wrapping | Proposed domain operation (NOT implemented) | Existing boundary |
|---|---|---|---|
| Discover named emitter | snapshot()/query({text,within,kind}); labels may collide; component refs are ephemeral | read allowlisted snapshot with effect instance ID, revision, stable emitter ID and layer ID | normalized emitters, selected emitter, schema |
| Set intensity | number input setValue via change callback | set layer opacity 0..1, explicit layer ID | changeLayer('opacity'), E.normalize, configure |
| Move X and Y | two number inputs, callback per field | one atomic set-position command with both logical coordinates (-16384..16384), exact emitter ID and revision | changeEmitter('x'/'y'), setFromScene, validated logical transform |
| Toggle visibility | switch or checkbox action, callback | set emitter/layer visible boolean by IDs, not toggle blindly | changeEmitter/changeLayer('visible') |
| Read anchor/geometry | cannot infer canvas objects from registered controls | read-only named anchor and bounds query; missing anchors explicit | scenePositionForEmitter/Layer, diagnostics |
| Curve control point | not a registered control, no synthetic click | explicit curve key ID/domain and schema operation (later review) | curve editor/core |
| Export/delete/replace/import | data-agent-confirm is a UI affordance, not sufficient authorization | denied in initial prototype; exact scoped user approval required for any future destructive/export action | busy guard, existing export workflow, #67/#70 |

Human display labels can collide even if stable IDs are unique; SDK word matching can be ambiguous. Use descriptive unique labels for accessibility but never persisted SDK ref or DOM index as effect identity. Label matching, DOM rerenders, selected emitter changes, and off-page remembered entries cannot authorize writes.

## Concrete evidence in current code

Read-only V8 probe (actual emitter-core and actual shared curve/color sources at repository baseline, no SDK installed): 16/16 assertions PASS. Used normalized existing explosion preset, enabled its two emitters, gave both identical human names, changed emitter1 x=123/y=-35 and glow opacity=.5; verified stable IDs, authored coordinates, exact half alpha and unchanged emitter2 primitive output. Hiding the glow removed only that layer; JSON round-trip exact; NaN, out-of-range position/opacity, string boolean, unknown property and duplicate emitter ID rejected, original sample preserved. This is CPU domain evidence, NOT agent transport or render acceptance.

Important integration blocker: emitter-ui commit sets its local doc before invoking onChange, and ui.html onChange sets cfg.multiEmitters before multiFx.configure. A failing configure can therefore leave rejected settings exposed in UI/config. This is a source observation, not a reproduced browser failure. Before a bridge, review and fix the transaction boundary in a separate approved existing-editor regression slice: validate candidate, configure/stage successfully, then publish one revision and refresh all UI; on failure preserve prior accepted state/selection/pose. Do not expose the current callback as an agent mutation API. Check runtime rollback and cleanup separately. No changes to these files in this research.

## Permission and proof contract for any later prototype

Proposed conservative defaults, pending explicit owner approval: a client-side editor actor (not a coding agent and not a GitHub publisher); read-only allowlisted snapshot, one optional explicit-user-enabled session for four reversible parameter edits above, no external host callbacks assumed. No automatic approval, hidden/private asset bytes, file paths, arbitrary script/canvas mutation, upload, download, deletion or export. Keep #70 as permission authority and #67 as exact-payload publication authority. Fresh schema/range/busy/ID/revision checks at execution, not only at discovery; commands carry operation IDs and source manual/agent, rejected/aborted operations cannot commit. Host must independently decide consent and record a receipt; SDK callback source/cancel and result values can inform evidence but an ok flag alone does not prove commit. Undo/redo, permission duration, actor identity and host integration remain unresolved for implementation; default deny until separately approved. Existing UX must work without bridge. Optional WebMCP registration only with available document.modelContext and explicit permission; absent API leaves ordinary editor usable, no unsupported-browser promise. Do not certify model-callback bypass/CCS: no installed native harness boundary was inspected. Reuse ordinary commands only; #71 owns such evidence.
